# 换电脑

之前骑车摔坏了屏幕（虽然只是屏幕坏了，而且买了新屏幕修好了），于是动了换电脑的心思。同时女朋友被我这么一提，又想起最后一次教育优惠的机会，两个人的歹念就互相促进起来。

省流，她换了 macbook air，我换了机械革命星曜14 锐龙 AI H365.

## apple

买 macbook air 没啥可说的，要在苹果里选，并且拒绝neo。

## I use arch btw

我的需求比较复杂，包括

- 重量，一直想要超轻本，1kg的。其实早早就盯上机哥的无界14，轻、接口多、续航好，而且听说内存涨价，lunar lake 有价格优势
- linux支持良好
- 外接显示器方便，希望有一个高规格接口转拓展坞连接电源、键盘、显示器等（已经有拓展坞了，但旧电脑接口规格不够，2021款的magicbook 14）
- 可能要写 C, rust, python, TS. 我想支持 pytorch, libtorch, ollama 等
- 想要回收处理旧电脑（因为瞎逛淘宝时发现有个 **机械革命14se intel**版有双硬盘插槽）

### misc

眼馋一个希未 r14 max，一个新牌子，但是配置挺好，而且 980g 重量，接口也不错。
一开始选的 R7 HX370 版本，差点就下单了，但是由于一系列各种复杂原因下延迟了。
等有机会再买时又研究了一下 cpu 对 torch 的支持，发现这一款cpu的核显很难用上rocm特性的torch，另一个版本的 Ultra 285H 要好一些。但是没货了。  
接着找其他牌子，翻到了更杂牌的 E人E本，甚至 898g 重量，同样用 ultra 9 285H cpu。但是电池容量、仅type-c接口、过于杂牌、价格又提高一档，使我望而却步。  
最后翻到去年的星曜14，而且在闲鱼有好价，终于下决定下单。

### Torch / LibTorch 基本内容

#### 基本概念

Torch 现通常指 **PyTorch**，是一个深度学习框架，核心功能包括：

- **GPU 加速的张量计算**（类似 NumPy）
- **自动求导的神经网络训练平台**
- **PyTorch**：Meta主导的深度学习框架，核心功能包括GPU加速的张量计算和自动求导的神经网络训练。
- **LibTorch**：PyTorch的C++前端，是官方最成熟的非Python接口，用于高性能推理和服务端部署，可避免Python GIL锁限制，API与Python版高度相似
- **其他非Python方式**：PyTorch Mobile支持Android/iOS；ExecuTorch面向嵌入式设备；社区提供R语言和Java的封装

#### LibTorch（C++ 前端）

LibTorch 是 PyTorch 的官方 C++ 接口，用于高性能推理和服务端部署，可避免 Python GIL 锁限制，API 与 Python 版高度相似。

| 平台              | 支持情况                                     |
| ----------------- | -------------------------------------------- |
| CPU               | 所有版本和平台均支持                         |
| NVIDIA GPU (CUDA) | 支持最成熟，通过`torch::kCUDA`指定           |
| Intel GPU (XPU)   | PyTorch 2.5起官方支持，通过`torch::kXPU`指定 |
| AMD GPU (ROCm)    | 逐步完善，需查阅具体版本文档                 |
| Apple MPS         | 实验性支持，通过`torch::kMPS`                |

#### 各硬件平台支持概览

| 硬件平台              | 支持情况    | 说明                                                |
| :-------------------- | :---------- | :-------------------------------------------------- |
| **CPU**               | ✅ 通用支持 | 所有版本均可在 CPU 上运行                           |
| **NVIDIA GPU (CUDA)** | ✅ 最成熟   | 需 GTX 900 系列及以上                               |
| **AMD GPU (ROCm)**    | ⚠️ 逐步完善 | ROCm 7.2+ 支持部分 Ryzen AI APU                     |
| **Intel GPU (XPU)**   | ⚠️ 原型支持 | PyTorch 2.5+ 在 Linux/Windows 上提供 Intel GPU 支持 |
| **Apple MPS**         | ⚠️ 实验性   | macOS 上通过 Metal 加速                             |

### 各 CPU 对 PyTorch 和 Ollama 的支持情况

#### AMD 平台

| CPU                              | PyTorch 支持                               | Ollama 支持                                                     |
| :------------------------------- | :----------------------------------------- | :-------------------------------------------------------------- |
| **Ryzen AI 9 HX 370** (gfx1150)  | ROCm 7.2 官方支持，但社区反馈配置仍较脆弱  | 需手动设置 `OLLAMA_IGPU_ENABLE=1` 等环境变量，Vulkan 后端可运行 |
| **Ryzen AI 9 HX 470** (gfx1150)  | ROCm 7.2+ 官方支持，与 HX 370 同为 gfx1150 | 预期与 HX 370 类似，需手动配置                                  |
| **Ryzen AI 7 365** (Radeon 880M) | ROCm 7.2+ 官方支持                         | 同属 Ryzen AI 300 系列，支持情况类似                            |

**关键进展**：ROCm 7.13 已正式支持更多 Ryzen AI 300 系列 APU。AMD Ryzen AI 300 系列（含 HX 370、HX 470 等）的 GPU 识别代号为 **gfx1150**，已纳入 ROCm 官方支持矩阵。

**注意事项**：

- PyTorch/LibTorch 主要利用 **GPU（Radeon 890M/880M）** 而非 NPU（XDNA 2），对 NPU 支持非常有限
- 需在 BIOS 中手动将 UMA 帧缓冲设为固定值（建议 2GB 以上）
- Linux 下 ROCm 对 APU 的支持仍属“预览”阶段，稳定性不如 NVIDIA CUDA 生态

AMD Radeon 890M / 880M（Ryzen AI 9 HX 370 / H 365）

**PyTorch / ROCm 支持：**

- **硬件识别**：GPU被识别为`gfx1150`（RDNA 3.5架构）。
- **官方支持声明**：ROCm已将Radeon 890M列入支持列表。
- **实际状态**：社区有用户成功从源码构建PyTorch以支持RDNA 3.5（gfx1150）加速。但ROCm对APU的支持仍属早期，有用户报告在Framework设备上运行PyTorch时，GPU处理到100%后会发生冻结或GPU重置。有用户尝试通过添加内核参数`amd.cwsr_enable=0`并降低分辨率才得以成功生成。
- **环境变量**：需设置`HSA_OVERRIDE_GFX_VERSION=11.0.0`来绕过检测【用户文档】。

**Ollama 支持：**

- **Ollama 0.24**：可正常使用GPU加速。
- **Ollama 0.30+**：因默认过滤规则将gfx1150（Strix Point APU）排除，导致回退到CPU运行。需设置环境变量`OLLAMA_IGPU_ENABLE=1`强制启用。
- **修复进展**：已有PR将gfx1150加入默认允许列表（与gfx1151并列），但尚未完全合并。
- **双后端支持**：新版Ollama可通过Vulkan和ROCm两个后端同时识别890M。有测试显示Vulkan后端性能甚至优于ROCm。

#### Intel 平台

| CPU                              | PyTorch 支持                                         | Ollama 支持                                          |
| :------------------------------- | :--------------------------------------------------- | :--------------------------------------------------- |
| **Core Ultra 9 285H** (Arc 140T) | PyTorch 2.5+ 提供 Intel XPU 原型支持；需 oneAPI 组件 | 通过 Vulkan 后端或定制镜像可运行；官方支持仍在完善中 |
| **Core Ultra 5 225H** (Arc 130T) | 同属 Arrow Lake 架构，XPU 支持路线相同               | 同 285H                                              |
| **Core Ultra 5 226V** (Arc 130V) | Lunar Lake 架构，需 Linux 内核 6.13+                 | 驱动和内核支持仍在开发中                             |

**关键进展**：

- PyTorch 官方文档确认：**Intel GPU (XPU) 支持从 PyTorch 2.5 开始**，在 Linux 和 Windows 上均可使用
- Arch Linux 已提供 `python-pytorch-opt-xpu` 包
- Ollama 通过 **SYCL 后端** 或 **Vulkan 后端** 可支持 Intel Arc GPU

**注意事项**：

- Intel 285H 的 NPU 算力仅 13 TOPS，远低于 AMD HX 370 的 50 TOPS
- Linux 下 XPU 支持属“原型”（Prototype）阶段，需较新内核和驱动

Intel Arc 140T（Core Ultra 9 285H）

**PyTorch 支持：**

- **官方支持**：PyTorch 2.5起正式支持Intel GPU（XPU后端）。
- **Linux现状**：已有用户在Fedora上通过安装`intel-compute-runtime`、`oneapi-level-zero`等组件尝试使用Arc 140T。但存在XPU后端报错（如"doesn't support querying the available free memory"）。
- **稳定性**：有报告称复杂模型反向传播可能导致崩溃或系统冻结【用户文档】。

**Ollama 支持：**

- Intel提供了基于IPEX-LLM的优化版Ollama，可调用核显的XMX加速单元【用户文档】。
- 官方Ollama对Arc核显的原生支持仍在完善中。

### 开发环境与编程语言的硬件性能侧重

#### 各场景对硬件资源的需求

| 开发场景                            | 侧重硬件              | 说明                                                                 |
| :---------------------------------- | :-------------------- | :------------------------------------------------------------------- |
| **Rust 全量编译** (`cargo build`)   | **核心数/线程数**     | 多核并行编译受益最大，AMD HX 370 (24 线程) 优于 Intel 285H (16 线程) |
| **Rust 增量检查** (`cargo check`)   | **单核性能**          | Intel 285H 单核领先约 10%                                            |
| **TypeScript/Node 开发**            | **单核性能**          | `tsc` 增量编译、热更新依赖单核响应速度                               |
| **C++ 大型项目编译**                | **核心数 + 内存带宽** | 并行编译多核占优；链接阶段依赖内存带宽                               |
| **Python 科学计算** (NumPy/PyTorch) | **多核 + 内存带宽**   | 数据加载和多线程计算受益于多核和高带宽内存                           |
| **FFmpeg 软编码**                   | **核心数/线程数**     | HX 370 (24 线程) 优于 285H (16 线程)                                 |
| **FFmpeg 硬编码**                   | **核显硬件单元**      | Intel QuickSync 在 Linux 下生态更成熟                                |
| **轻量 AI 推理** (Ollama/llama.cpp) | **CPU + 内存容量**    | 内存容量是关键（Colibri 项目需 ≥25GB）；核显加速目前属“折腾型”       |
| **PyTorch 训练**                    | **GPU + 内存带宽**    | 需核显或独显加速；内存带宽影响数据加载效率                           |

各场景对CPU核心/线程的依赖

| 开发场景                                    | 核心/线程敏感度    | 说明                                                  |
| ------------------------------------------- | ------------------ | ----------------------------------------------------- |
| **Rust编译**（`cargo build`）               | **高**             | 全量编译高度依赖多核并行，锐龙HX370（24线程）优势明显 |
| **C++编译**                                 | **高**             | 大型项目并行编译受益于多核                            |
| **Python科学计算**（NumPy/PyTorch数据加载） | **中高**           | 多核和内存带宽重要                                    |
| **TypeScript/Node开发**                     | **低（单核主导）** | `tsc`增量编译、热更新主要依赖单核性能                 |
| **日常响应/脚本启动**                       | **低（单核主导）** | 单核频率决定体验                                      |

#### 内存的重要性

- **Colibri 项目**（基于 GLM 5.2 的 CPU 推理）需要约 **25GB 内存**，因此 **32GB 是硬性门槛**
- 核显（无论是 AMD Radeon 890M/880M 还是 Intel Arc）共享系统内存，内存容量和带宽直接影响可运行模型大小和训练速度
- AMD HX 370/HX 470 支持 **LPDDR5X-8533 MT/s**，Intel 285H/225H 支持 **LPDDR5X-8400 MT/s**
- **BIOS设置**：AMD平台需手动将UMA帧缓冲设为固定值（如2GB或更高），避免动态分配导致的识别失败
- AMD平台支持LPDDR5x-8000 （or 8533, not sure, and do not know what that mean），Intel平台支持LPDDR5/x 8400 MT/s。
- 内存带宽是核显AI推理的**最常见瓶颈**，直接影响可运行模型大小和推理速度

#### 功耗墙对轻薄本性能的影响

- 轻薄本为控制散热，实际持续功耗远低于 CPU 标称 TDP
- 例如搭载 Intel 285H 的轻薄本烤机实测仅 **35W** 左右，远低于 45W 标称
- 选购时跑分仅作参考，实际编译等长时间满载任务需关注具体机型的散热设计和功耗墙设置
- 轻薄本（1kg左右）性能释放普遍保守，持续功耗远低于CPU标称TDP
- Intel Ultra 9 285H在50W功耗下即可达到前代90W的性能水准，能效比提升显著。
- AMD HX 370默认28W，能效优秀，适合轻薄本长续航
